# Dashboard evaluation

Deliver an evidence-linked evaluation and a bounded disposition for the exact artifact revision. Own the integrated challenge across task correctness, data meaning, composition, responsiveness, accessibility and disruptive updates. Read [handoffs](../../references/workflow-contract.md) for the minimal review packet and re-entry rules.

1. **Establish evidence and independence.** Read the current brief or recover stated tasks from supplied evidence, raw data/fixtures and artifact identity. Inspect the actual artifact before accepting builder claims. Use a fresh evaluator without author reasoning when authorized and available; otherwise disclose self-review and its limits. A new thread or agent is not automatically authorized. Missing goals narrow the review's task conclusions; they do not prevent useful bounded semantic/accessibility findings. Do not infer intended truths from a polished screen or a preferred answer key.
2. **Challenge task and data correctness.** Derive expected answers independently from raw input. Try realistic decisions and plausible wrong conclusions. Verify valued task coverage and agreed preservation or replacement decisions against the redesign. Read [data meaning](../../references/data-meaning.md) for population, observation-state, scale, denominator, uncertainty and statistical checks; [service semantics](../../references/service-semantics.md) only for service dashboards. Explain any missing source fact that prevents a conclusion. Keep semantic requirements, standards, heuristics and taste separate using [sources](../../references/sources.md).
3. **Inspect the experience at its delivered fidelity.** Read [verification](../../references/verification.md) and examine rendered initial desktop/narrow views, comparisons, long labels and detail paths. For working prototypes exercise keyboard/nonhover access, filtering, return, active modal updates, focus and scroll; read [monitoring/interaction](../../references/monitoring-interaction.md) for live/pause/alert behavior. Distinguish source inspection, screenshots, browser execution, actual AX-tree exposure, accessibility-client behavior and reader observation. Static sketches cannot pass runtime criteria; unavailable tools produce specific untested checks, not fabricated passes.
4. **Report findings and disposition.** For each finding name location/state, observation, decision consequence, severity, proposed repair and smallest recheck. Separate deterministic failures, reviewer judgments, direct user acceptance and untested behavior. Synthetic evaluator scores cannot establish user acceptance; a user-reported workflow failure reopens the relevant conclusion even after a synthetic pass. Prioritize false certainty, hidden evidence gaps, unsupported comparisons, inaccessible essential actions or lost context over polish. State acceptable-for-which-purpose, revise or blocked-for-which-conclusion; avoid one overall pass implying production readiness or conformance. Stop when material conclusions have evidence and limits.
5. **Hand back the next action.** Return the evaluation report keyed to brief and artifact revisions. Route local design/interaction fixes to dashboard-prototyping and changed jobs/semantics to dashboard-discovery. Do not edit during review unless separately requested; keep a later repair and its recheck distinct. Retain earlier reports and rerun only affected checks plus justified regressions. When an implementation spec or tickets are requested, provide this evidence to the existing to-spec/to-tickets workflow instead of replacing it.

Compare alternatives under equivalent tasks/data and disclose fidelity or budget confounds. Do not force a winner. Synthetic success alone does not establish skill efficacy or real-world task fit. No install, publication or live-system action is implied.

## Visual refinement

Read [visual-craft.md](../../references/visual-craft.md) for composition, typography, spacing, semantic color, responsive behavior and browser inspection. Apply it to the existing task and design system, not as a cosmetic template. Record the visual thesis and review actual target viewports; do not trade data honesty or preserved workflows for polish.
