# Dashboard discovery

Produce one durable design brief that another designer can use without this chat. Own the combined discovery work: the user's job, evidence, consequential questions and information organization. Do not fragment these into separate skills. Read [handoffs](../../references/workflow-contract.md) for artifact identity, entry/re-entry and downstream boundaries. These are draft procedures, not validated efficacy claims.

1. **Establish the job and scope.** Inspect the existing brief, relevant authorized artifacts and current request before interviewing. Name audience, context, one to three decisions, cadence and costly mistakes. Distinguish monitoring from exploration and the intended initial viewing conditions. For redesigns, investigate valued existing workflows and explicit preservation constraints before proposing changes; distinguish observed needs from assumptions using the shared handoff contract. Record authorization separately from design intent. Stop when each main decision has a recognizable success condition.
2. **Inspect the available data.** Look at actual supplied/authorized samples, metadata and states; do not substitute plausible field names for evidence. Record grain/keys, population, units, numerator/denominator, aggregation, baseline, period/time zone, provenance, coverage, quality and freshness. Read [data meaning](../../references/data-meaning.md) for rates/time/scale/statistical questions, and [service semantics](../../references/service-semantics.md) only for service status. Mark absent evidence and synthetic assumptions explicitly. Stop when each candidate measure is interpretable or its material ambiguity is recorded.
3. **Resolve consequential questions.** Ask only questions whose answers change audience, task, data interpretation, safety, scope or a consequential design choice. Use available evidence for cheap lookups. Progress on independent work while answers are pending; do not invent thresholds, permissions or facts. A provisional brief may leave blockers open without pretending it is ready for dependent work.
4. **Organize the information.** Connect decisions to measures, comparisons, evidence states, initial-view priorities and detail paths. Separate enduring importance, current urgency and observation quality. Read [monitoring/interaction](../../references/monitoring-interaction.md) for live attention or exploration. State representation candidates and tradeoffs without prematurely prescribing components or polishing a screen. Stop when another agent can explain why each information group exists.
5. **Deliver and hand off.** Write/update the single design brief using the shared contract, with evidence locators, resolved decisions, assumptions, open questions and readiness for a stated next step. Read [sources](../../references/sources.md) when attributing claims or choosing between guidance. Pass the current brief revision to dashboard-prototyping if building is requested; do not launch it merely because discovery finished.

On re-entry, preserve agreed facts, identify the changed job/data/constraint and revise only affected decisions. Existing prototypes and evaluations become affected or superseded evidence, not silently current approvals. When engineering specification or tickets are requested later, use the available to-spec and to-tickets skills; this brief is design input, not their replacement. No installation, publishing or tracker mutation follows from this skill alone.
